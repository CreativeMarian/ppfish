## 一、自动发货链路总览

```
买家在闲鱼拍下商品
      │
      ▼
ppfish 捕获订单（websocket 实时监听）
      │
      ├── 卡券类型 = 蜜蜂直充(mf_api) → 按 api_config 进入发货流程：
      │      ① 充值链接模式：发充值链接 → 买家网页填手机号 → 蜜蜂放单 → 查单 → 通知买家
      │      ② 兑换链接模式：蜜蜂放单 → 生成兑换链接 → 直接发买家 → 查单 → 确认发货
      │
      └── 其他类型（固定文字/批量数据/API接口/图片）→ 直接按配置发送
```

核心概念：

- **卡券（Card）**：商品的"发货规则"。一个商品可以关联多张卡券（多规格时按规格匹配）。
- **蜜蜂直充（mf_api）**：卡券类型之一，对接蜜蜂汇云 API，自动放单/查单/发链接。
- **api_config**：卡券里保存的 JSON 配置，蜜蜂直充的所有参数都在这里。

## 二、货源接入：蜜蜂汇云

### 2.1 入驻蜜蜂汇云

1. 打开蜜蜂汇云官网（merchant.task.mf178.cn / merchant.feedov.com）注册账号。
2. 完成实名认证（个人/企业均可）。
3. 在"报价管理"开通所需业务的报价（会员直充、话费、餐饮代下单等，部分需联系客服开通）。
4. 充值少量余额（测试订单用，几十元即可）。
5. 在后台获取你的 **AppKey / AppSecret**（个人中心 → API 信息）。

### 2.2 配置系统密钥（.env）

在项目根目录 `.env` 中配置蜜蜂凭证：

```env
# 蜜蜂汇云
MF_APP_KEY=你的AppKey
MF_APP_SECRET=你的AppSecret
MF_BASE_URL=https://merchant.task.mf178.cn

# 充值链接页面地址（买家打开填手机号的页面）
# 本机/服务器可用 http://IP:9000 或已绑定的域名
MF_RECHARGE_BASE_URL=http://43.226.44.86:9000
```

> ⚠️ 修改 .env 后需要重启 `ppfish-websocket` 服务生效：
> ```bash
> systemctl restart ppfish-websocket
> ```

### 2.3 查询蜜蜂商品与价格

在蜜蜂后台"买方管理端 → 产品中心 → 已开通业务"可查看商品及采购价。
每个商品有唯一的 **商品ID（miniunit_id）** 和 **SKU（goods_sku）**，配置卡券时需要用到：

| 业务 | 举例 | 说明 |
|------|------|------|
| 会员直充 | 腾讯QQ会员、爱奇艺会员等 | 需买家填手机号/账号，走充值链接模式 |
| 话费充值 | 全国话费快充 | 需买家填手机号，走充值链接模式 |
| 餐饮代下单 | 麦当劳套餐、瑞幸咖啡 | 无需手机号，放单后返回兑换链接，走兑换链接模式 |

> 例：麦当劳"中薯条" miniunit_id=`1002299`；瑞幸"标准美式" miniunit_id=`1002308`。

### 2.4 两种发货模式说明

| 模式 | 适用场景 | 流程 | api_config 关键字段 |
|------|---------|------|---------------------|
| **充值链接模式**（默认） | 会员直充、话费充值等需填手机号的业务 | 买家付款 → 系统发充值链接 → 买家网页输手机号提交 → 蜜蜂放单 → 查单成功 → 通知买家 | `recharge_page: true`、`require_account: true`、`datas: {"target": "{account}"}` |
| **兑换链接模式** | 餐饮代下单等直接发链接的业务 | 买家付款 → 系统直接放单 → 生成专属兑换链接（7天有效）→ 发买家 → 查单成功 → 确认发货 | `recharge_page: false`、`require_account: false`、`datas: {}`、`success_message` 支持 `{voucher}` |

**两种模式的 api_config 完整示例：**

充值链接模式：
```json
{
  "miniunit_id": "1002299",
  "goods_sku": "SK000840",
  "require_account": true,
  "recharge_page": true,
  "poll_delay": 60,
  "poll_interval": 60,
  "max_poll": 8,
  "datas": {"target": "{account}"}
}
```

兑换链接模式：
```json
{
  "miniunit_id": "1002299",
  "goods_sku": "SK000840",
  "require_account": false,
  "recharge_page": false,
  "poll_delay": 60,
  "poll_interval": 60,
  "max_poll": 8,
  "datas": {},
  "success_message": "🎉 麦当劳中薯条已下单成功！\n您的专属兑换链接（7天内有效）：\n{voucher}\n点链接选择门店兑换取餐～"
}
```

> 参数说明：`poll_delay` 放单后首次查单等待秒数（≥60）；`poll_interval` 查单间隔；`max_poll` 最大查单次数（约 8~10 分钟出结果）。这些参数后台新建卡券时自动配置，一般无需手工填写。

## 三、新增卡券详细步骤（后台操作）

### 3.1 进入卡券管理

登录 ppfish 后台 → 左侧菜单 **「卡券管理」**（页面路径 `/cards`）。

页面功能：搜索、按类型筛选、新建卡券、编辑、复制、删除（单个/批量）、关联商品。

### 3.2 新建卡券（蜜蜂直充）

点击 **「新建卡券」** 按钮，弹出表单：

1. **卡券名称**（必填）：例如 `麦当劳-中薯条`、`腾讯QQ会员-月卡`。名称与规格一起用于匹配订单。
2. **卡券类型**（必填）：选择 **`蜜蜂直充`**。
3. **蜜蜂直充配置**区域：
   - **上游商品ID（miniunit_id）**（必填）：填蜜蜂后台该商品的商品ID（如 `1002299`）。
   - **发货模式**：
     - `充值链接模式（买家填手机号充值）`：会员直充/话费用。
     - `兑换链接模式（餐饮代下单，直接发链接）`：餐饮代下单用。
   - **发货文案模板**（仅兑换链接模式，选填）：自定义发给买家的成功文案，支持 `{voucher}` 占位符（自动替换为兑换链接）。留空用系统默认文案。
4. **备注信息**（选填）：会与发货内容一起发送。
   - 非图片类型填写备注时**必须包含 `{DELIVERY_CONTENT}` 变量**（必填，代表发货内容）。
   - 可选变量：`{order_id}` 订单ID、`{item_id}` 商品ID、`{item_title}` 商品标题、`{buyer_name}` 买家昵称、`{buyer_id}` 买家ID、`{seller_name}` 卖家昵称。
   - 用 `######` 分隔符可将内容拆分为多条消息依次发送。
5. **多规格卡券**（选填）：如果同一商品不同规格（如月卡/季卡/年卡）对应不同上游商品，开启后填写"规格名称 + 规格值"，每个规格建一张卡券。自动发货时精确匹配订单规格。
6. 点击 **「保存」**。

> 💡 **快速添加多个规格**：建好第一张卡券后，点卡券行的 **「复制」**，会预填全部配置，只需改名称（和规格）即可，适合"周卡/月卡/季卡"这类批量录入。

### 3.3 关联商品

卡券建好后，需要把卡券**关联到闲鱼商品**（一个卡券可关联多个商品）：

- 方式一（卡券侧）：在卡券管理列表**选中一张卡券** → 点 **「关联商品」** → 选择要关联的闲鱼商品。
- 方式二（商品侧）：进入 **「商品管理」** → 找到商品 → **发货配置** → 添加卡券。

> 自动发货时，系统根据订单的商品 ID 找到关联的卡券进行发货；多规格商品则按"商品ID + 规格"精确匹配。

### 3.4 验证链路（测试单）

1. 在蜜蜂后台"放单/测试"功能下一单对应商品（或直接让买家下一单）。
2. 观察 websocket 日志：
   ```bash
   journalctl -u ppfish-websocket -f
   ```
   应看到：捕获订单 → （充值链接模式：发送充值链接 / 兑换链接模式：直接放单）→ 查单 → 发送结果。
3. 充值链接模式：打开充值链接，输入手机号提交，应提示"充值处理中"，随后查单成功通知买家。
4. 兑换链接模式：买家应收到带兑换链接的消息，点开链接可选择门店兑换取餐。
5. 后台「订单管理」确认订单状态为已发货，发货内容已落库。

## 四、发布闲鱼宝贝

ppfish 自带闲鱼商品发布功能（后端 `xianyu_direct_publisher` 调闲鱼官方发布接口）。

### 4.1 发布入口

后台 → 商品发布功能（使用前提：闲鱼账号已登录、Cookie 有效）。

### 4.2 关键参数

| 参数 | 说明 | 示例 |
|------|------|------|
| account_id | 闲鱼账号ID | 2209883184223 |
| title | 标题，**≤30字**（超长会报 `FAIL_BIZ_TITLE_LENGTH_TOO_LONG`） | 麦当劳套餐代下单 全国门店通用 兑换链接秒发 |
| price / original_price | 售价/原价 | 12.9 / 19.9 |
| cat_id / channel_cat_id / leaf_id / tb_cat_id / path | 平台分类5件套 | 西式快餐：cat_id=50025461、channel_cat_id=201421503、leaf_id=1831、tb_cat_id=50015756 |
| images | 服务器绝对路径数组（先用上传接口拿路径） | /www/wwwroot/ppfish/backend-web/static/uploads/products/xxx.jpg |
| specifications / sku_rows | 规格（price>0, stock） | 中薯条12.9/板烧鸡腿堡14.9/... |
| delivery_method | 发货方式 | pickup（自提/虚拟） |
| shipping_method | 运费方式 | none |

### 4.3 流程

1. 调用类目推荐接口 `/api/v1/product-publish/category/recommend` 获取商品分类。
2. 准备图片：搜索/制作商品图 → 上传到服务器（发布图片接口返回绝对路径）。
3. 调用发布接口 `/api/v1/product-publish/publish/single`。
4. 发布成功后返回 item_id，系统自动 sync 入库（商品出现在商品管理）。
5. 到卡券管理把新商品关联上对应卡券 → 全链路打通。

> ⚠️ 注意：闲鱼对部分类目有禁售规则（如话费直充曾被静默删除），发布前确认类目合规。

## 五、接入其他货源渠道（标准系统协议）

蜜蜂汇云使用的对接协议是业内通用的 **91卡券「标准系统」协议**，多个货源平台（如深度数卡、91卡券自有货源等）使用同一套协议。ppfish 已实现该协议的完整客户端（放单/查单/余额/商品列表），**接入同协议平台时基本不需要改代码**。

### 5.1 标准系统协议核心要素

| 要素 | 说明 | 蜜蜂示例 |
|------|------|---------|
| 接口网关 | 平台 API 地址 | `https://merchant.task.mf178.cn` |
| 用户ID | 平台分配的用户编号 | 见 .env MF_APP_KEY |
| 用户密钥 | 平台 API 密钥 | 见 .env MF_APP_SECRET |
| 货源方商品ID | 平台上每个商品的唯一ID | miniunit_id（如 1002299） |

### 5.2 主要接口

| 接口 | 用途 |
|------|------|
| upload_order | 放单（提交订单给货源平台） |
| order_info | 查单（查询订单状态/卡密/兑换链接） |
| order_refund | 退款 |
| account | 查询余额 |
| productGoodsListNew | 商品列表（参数在 datas 里传 `{"type":1}`） |
| productGoodsPriceSave | 修改商品售价 |

### 5.3 接入新平台的步骤（以深度数卡为例）

1. 注册平台账号 → 实名认证 → 签约商户（签约才有 API 权限和最低价，注意签约费不退）。
2. 打开 API 开关并重置密钥，保存**会员编号 + 密钥**。
3. 在系统 `.env` 中新增一套凭证（或复用现有凭证结构）：
   ```env
   # 新平台
   XXX_APP_KEY=会员编号
   XXX_APP_SECRET=密钥
   XXX_BASE_URL=https://平台网关
   ```
4. 用平台的测试商品调放单/查单接口，验证协议兼容性（同协议通常直接可用）。
5. 验证通过后：查商品列表 → 选品 → 发布闲鱼宝贝 → 新建卡券（type=`mf_api`，填平台的 miniunit_id）→ 关联商品。

> ⚠️ 关键：接入前务必**确认平台的接口路径、签名方式与蜜蜂一致**（都是标准系统协议则一致）。有差异时需在 `websocket/app/services/xianyu/mf_api_handler.py` 中适配。

## 六、常见问题与排错

### Q1：卡券保存失败，报 "Incorrect string value" 或含 emoji 的乱码

数据库 `api_config` 列是 utf8（非 utf8mb4），**不能存储 emoji**。解决办法：文案中的 emoji（如 🎉）换成纯文字（如 `【下单成功】`）。

### Q2：充值链接打不开 / 网页报错

- 检查 `.env` 中 `MF_RECHARGE_BASE_URL` 是否可访问（本机/服务器 + 端口）。
- 检查服务器防火墙/安全组是否放行 9000 端口。
- 如果域名没配 HTTPS，链接用 `http://`，不要用 `https://`（否则证书错误打不开）。
- 检查 `ppfish-backend` 服务是否正常（充值页由后端服务提供）。

### Q3：买家在充值页输入手机号点"立即充值"提示"系统繁忙"

- 查看后端日志定位具体报错（余额不足、参数错误、网络超时等）。
- 检查蜜蜂余额是否充足。
- 检查 api_config 的 miniunit_id/goods_sku 是否正确。

### Q4：餐饮代下单买家收不到兑换链接

- 确认卡券是**兑换链接模式**（`recharge_page: false`、`require_account: false`、`datas: {}`）。
- 检查 websocket 日志是否成功放单、查单是否返回 `ys_cards[0].card_pwd`。
- 兑换链接**7天内有效**，超时未兑换需走售后。

### Q5：多规格商品发错卡券

- 确认每个规格都建了卡券，且"规格名称 + 规格值"与订单中的规格完全一致。
- 规格不匹配时不发货，先下一单看订单管理里的规格信息，再修正。

### Q6：发布宝贝报 "标题过长"

闲鱼标题限制 **30 字**，缩短标题后重试。

### Q7：修改 .env 或代码后不生效

重启对应服务：
```bash
systemctl restart ppfish-backend
systemctl restart ppfish-websocket
systemctl restart ppfish-scheduler
```
